Claude Code Lists and Publishes My KDP Books. One Box Is Mine

Written by hybs02

KDPincomeClaude Codeautomation

If you've let AI write your Kindle books and the listing is where you're stuck, you can hand the form to Claude Code too, all but one checkbox. These are the places where it needed a rule, and the one place it needs me.

At the end of October 2026, Claude Code listed two of my ebooks on KDP. It drove my own Chrome through the Claude in Chrome extension, so it used the KDP login I already had and never handled my password. It filled in the title, description, keywords, categories, files and price from metadata it had produced with each manuscript, and stopped before the Publish button. I read a summary, said go, and both went into review. As of November 5, both are on sale.

Since November 8, it lists, publishes and reprices on its own, as a daily scheduled run. The one thing I do is tick a checkbox.

That came after five months of not listing them, which I wrote about in the post about generating eight books in a day.

The setup is small. You install the Claude in Chrome extension, start Claude Code with claude --chrome (or run /chrome inside a session), and stay signed in to KDP in that browser. It needs a paid Claude plan.

Read the shelf and the weekly count first

The first thing Claude Code does now is read the bookshelf page in my KDP account and compare it with my tracking file. The first time it did that, it found a book my file called a draft that had been on sale for months. The rule that came out of it: the bookshelf is right and the file is wrong. When they disagree, the file gets corrected to match the shelf, and only then does anything else start.

The second thing is the weekly count. As of October 2026, KDP's help pages say you can create two new ebook titles a week, and submit two for the first time, with the count resetting on Sunday at 00:00 UTC. Saving a new title as a draft uses one of the two. So does a title you set up by hand outside the routine, which is another reason to read the shelf first.

At the end of October, two books used up that week's slots. Two more used the first week of November's. As of November 12, six of the original eight are on sale, one is in review, and one is still unlisted.

I don't know what the form does if you go over the cap, and I haven't tested it. The routine doesn't start a listing when the count says zero.

Two things my metadata got wrong

The description box is a rich-text editor. My generated metadata had paragraphs separated by blank lines, and entered that way, every paragraph ran together into one block. The book that had been on sale since early June had exactly that: its whole description as one wall of text, on the store page, for five months.

Now the metadata carries a second version with each paragraph wrapped in paragraph tags, and Claude Code sets the editor's contents to that version directly instead of pasting. If you paste by hand, paste formatted text, not the tags. Typed into the box, the tags would likely show up as text.

The categories were the other problem. My metadata wrote them as three-level paths, and some of those paths came from the paperback category list, which isn't the same tree as the Kindle store's. At least two ended in a category the Kindle store doesn't have.

The rule now is to walk the category picker one level at a time, take the matching category if there is one and the nearest one if there isn't, and put a table of "the metadata said this, I chose this" in its report. I'd rather see a substitution than find out later that a book is filed somewhere odd.

Where the form fought back

The manuscript and cover uploads aren't kept until you press "Save and Continue." During one listing the session timed out between uploading and saving, and both files had to go in again. Now each book is uploaded and saved on its own before anything else happens.

After an upload, KDP processes the file for a while. Claude Code checks the page every few seconds until the processing message is gone, because one long wait in a single step timed out at around 45 seconds. Then KDP runs its own quality check on the manuscript. When it passes, it says so in a line about having found no spelling or image problems. Sometimes that check sits at "running" for minutes, and the page can still be saved while it does.

Right after a page opens, a dark overlay sometimes covers it for a moment. Clicks during that moment do nothing, and nothing tells you.

Then the price. I price new books at $0.99 to start, and at that price KDP offers only the 35% royalty option (70% needs a list price of at least $2.99). About seven days after a book is published, the routine raises it to $4.99 and switches it to 70%. If the US price goes in before the royalty is chosen, the other marketplaces aren't filled in from it. The fix was to choose the royalty first and then enter the price again. The royalty radio button also ignored the usual way Claude Code clicks things on a page, so it clicks by position instead.

Between that overlay and this button, every click is now followed by a read-back to check it took.

The AI disclosure is mine to confirm

KDP asks whether the book contains AI-generated content, and for these books it does. Claude Code answers those questions:

  • Text: AI-generated, the whole work, with minimal or no editing.
  • Translation: none.
  • Images: none.
  • Tool named in the free-text field: Claude.

The images answer needs a reason. KDP defines AI-generated images as ones created by an AI-based tool, and that includes covers. My covers are shapes and type drawn by a Python script. No image model made them, though Claude wrote the script. I read a script-drawn cover as outside that definition. If your cover came from an image generator, it's inside it, and the answer is yes.

After a manuscript or cover upload, KDP shows a checkbox confirming that your answers are true. Right now it's a single box, in the accessibility section. That one it can't tick for me. When it tried, Claude refused the click and asked me instead. It's a statement from the person publishing, so it has to come from me.

The tick isn't kept until "Save and Continue" is pressed, and reloading the page before that clears it. That held one book up for four days, November 9 to 12. So Claude Code leaves the tab open at the box, sends me a notification, and waits up to 15 minutes. Once the box is ticked, it saves and carries on. If I miss that window, I tick it and press Save and Continue myself, in the same tab. When it lists two books, it brings both to the box in two tabs and asks me once.

The listing tool for the murder mystery game in the post about the digital products I never listed is set up to stop one step earlier, before its publish button.

Before Publish, it reads the summary back from the page (title, subtitle, author name, the three categories and any substitutions, keywords, the AI answers, the quality check result, price, and royalty) and compares it with the metadata. If anything disagrees or the quality check found errors, the book stays a draft. The table goes into its report.

What the slow part is now

The files had to be right before any of this (the pre-listing check is in the eight-books post). A form-filling tool can only enter what the files say.

Listing used to be the step I didn't do. Now my part of the form is one box. Whether a book is fit to sell is settled before it reaches the form, by machine checks and a blind read by a separate Claude instance. What's slow now is the weekly cap, and a box I don't tick in time.

None of this sells books. The two listed at the end of October haven't been on sale long enough to say anything about sales. The one on sale since June sold no copies in the 30 days before November 1.

If you try this yourself, start with the shelf, not the form:

Read my KDP bookshelf and list every title with its status and price. Compare it with my tracking file and show me every row where they disagree. Don't change anything in KDP.

Then, for one book:

Using Claude in Chrome, start a new Kindle eBook in KDP from the metadata in this folder. Save after each upload, choose the royalty before entering the price, and read every field back after setting it. Leave the AI confirmation checkbox for me. Stop before Publish and show me a table of every field, including any category you had to substitute.
