I Built Tools to Sell Digital Products and Listed Zero

Written by Automating the Boring Parts

incomeside incomeClaude Codefailure log

If AI has made your digital products and none of them are on sale yet, this is what that looks like on my end, with the numbers.

On June 2, 2026, I had Claude Code build me a small tool for selling digital products. It plans a product, drafts the listing text, and records sales. It came with a 90-day plan: three products in the first week, thirty by day ninety.

On November 1, the tool shows zero products and zero sales.

What I built

It's a command-line tool that runs entirely on my PC. It doesn't connect to any outside service.

CommandWhat it does
ideasLists product types that tend to sell without upkeep: prompt packs, templates, short guides
newPlans one product and creates a working folder and a brief for it
listingDrafts the text for the product page
publishRecords the URL once a product is listed
saleRecords a sale and its amount
dashboardShows product count, sales, and the suggested next step

The ideas list has seven product types, each rated on demand, ease of making, and how little upkeep it needs once it's up: prompt packs, Notion and spreadsheet templates, short PDF guides, Excel templates, printables, design assets, and code templates. Prompt packs were rated highest on all three. I never chose a category.

The plan that came with it described the split like this. The tool keeps track, Claude makes the content, and I "just press the publish button."

The dashboard on November 1, trimmed and paraphrased:


Products : 0  (listed 0 / in progress 0)
Sales    : 0
Next step: aim for 5 products first. The more you have, the better the odds one sells.

It has been giving me the same next step for five months.

I never started product one. The new command, which creates the first product folder, has never been run.

I switched plans the same day

On the evening of June 2, the day the tool was built, I asked Claude Code for something else: a setup that keeps running with no listing work at all, not even pressing a publish button. That became the automatic publishing pipeline behind this site.

Looking at that request now, the thing I was avoiding was the listing itself. The product tool was set up to stall at that step from the first day, because I had already decided I didn't want to do it.

The second tool: ready, not listed

At the end of July, I had Claude Code build a second tool. My brief was short: a new income source, separate from everything I already had, that could bring in a small amount every day without upkeep. Claude Code looked at the options with me, and we landed on murder mystery party games: scripted mysteries a group plays together, with a rulebook, a role sheet for each player, a host guide and an ending. They sell as downloads on marketplaces for independent creators.

I picked it after looking at one such marketplace on July 30. Murder mystery games had about 1,400 listings there. Tabletop RPG scenarios on the same site had about thirty times as many, yet the most popular murder mysteries had been favorited 4,000 to 12,000 times. Prices were mostly a few dollars to around twenty. The product is all text, so the thousandth copy costs the same as the first: nothing.

The first game was written by the end of July and kept being revised. On October 30 it passed every check the tool runs: exactly one culprit, a secret for every character, and every inconsistency the AI testers flagged either fixed or marked as deliberate.

The blind test works like this. The tool hands a fresh AI instance only what players would see, with no access to the solution, and asks it to name the culprit and give odds for every suspect. Two instances read the first half of the game. Both picked the right culprit, but only at 35%, with the other suspects sharing the rest, which is what the first half is for. Two more read everything a group has by the end and named the culprit at 74% and 75%. When the script changed in substance, the old results were filed away and the test ran again, and there are five earlier rounds on file. Small wording fixes were logged without a rerun.

Most of the listing work is in the tool too. It produces the product title, tags, description and cover image, and a Claude Code skill is written to fill in the marketplace's listing form in the browser and stop before the publish button. That skill hasn't run on the real form yet, because there's no shop to list in. The price is worked out: this marketplace takes a percentage of each sale plus a fixed fee per order, so at the lowest price I looked at, fees would take about 21% of each sale, and at the default price I set, about 9% (fees as of July 2026).

The tool's final check lists one thing left. It's the name I'd sell under, and that field is empty. Opening a shop and choosing the name is mine to do, and I haven't.

What's left between "finished" and "for sale"

This is the list of what stands between a finished product and a live listing. With the first tool, I never got to any of it. With the second, the tool has the last three rows prepared, but none of it has been tried on the real marketplace, because the first row isn't done.

StepWhat it involves
Open a shopCreate it and choose the name you sell under
Product pageTitle, description, price, preview images
RulesCheck how the marketplace treats AI-made products, especially bulk listings
Last readRead the thing yourself before pressing publish

None of it is hard. There's no deadline, though, and nothing breaks if you don't do it.

Here too, the stall was in the part that wasn't automated. This blog went quiet for 99 days, which I wrote about in the post before this one, because publishing was automated and adding posts wasn't. With the second tool, most of the listing is prepared, though not yet tested on the real form, and what's left is a decision.

If yours are made but not listed

  • Count what's listed, not what's finished. My dashboard has said 0 since June.
  • Write down every step between finished and live, and mark which ones are decisions rather than tasks. A tool can take over the tasks. Mine came down to one decision.
  • Ask Claude Code for the listing, not just the product. Something like this:

For the product in this folder, write the listing title, description, tags and price, list every step to publish it on my marketplace, and tell me which steps need a decision from me.

I haven't decided what's next

I haven't decided whether to keep going or drop it, or when I'll pick the name.

In money, I haven't lost anything. Both tools run on my PC, and the Claude subscription they use is one I pay for anyway. What I lost is information. If the plan had run, thirty products would have been up by the end of August, and I'd know which kinds sell. This site earns nothing either, so far. When a product goes up, the numbers will be here.
